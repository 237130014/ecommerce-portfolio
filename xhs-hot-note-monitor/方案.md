# 小红书近期热门笔记抓取 — 项目方案

> 通过指定关键词搜索小红书笔记 → 筛选「近 7 天 + 最多点赞」→ 抓取标题 / 正文 / 封面图 / 链接 → 汇总成表格 → 延伸出 Web 看板。
> 项目代号：`xhs-hot-note-monitor`

---

## 一、需求拆解

| 需求 | 说明 | 小红书网页版对应能力 |
|------|------|---------------------|
| 关键词搜索 | 输入一个或多个关键词，逐个搜索 | 搜索页 `/search_result?keyword=xxx` |
| 近 7 天筛选 | 只保留一周内发布的笔记 | 筛选「发布时间 = 一周内」 |
| 最多点赞 | 按点赞数降序取 Top N | 排序「最多点赞」 |
| 抓取字段 | 标题、正文、封面图、链接 | 列表页 + 详情页 |
| 汇总表格 | 结构化 CSV/Excel | 脚本生成 |
| Web 看板 | 瀑布流卡片 + 搜索筛选 | 复用竞品监控看板样式 |

---

## 二、技术路线对比

| 方案 | 原理 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| **A. Playwright 浏览器自动化** | 真实浏览器 + 登录态，从 `window.__INITIAL_STATE__` 提取数据 | 稳定、反爬友好、贴合「模拟真人行为」诉求 | 速度慢、依赖登录态 | ✅ 推荐 |
| B. 逆向签名 x-s/x-t | 还原混淆 JS 签名算法，用 requests 直接打接口 | 快、可规模化 | 密钥约 5 分钟更换一次、极易失效、维护成本高 | 备选 |
| C. requests + Cookie | 直接请求接口 | 简单 | 缺签名直接 461、IP/账号秒封 | ❌ 不可行 |

**结论**：选 A。核心难点（无公开 API、反爬、登录态）都用「真实浏览器 + 登录态 + 仿人操作」这一套来兜，与我们上一版竞品监控技能同一思路。

    ├── fix_images.py         # 封面图下载（签名临时 URL 及时下载 + 去重 + 落盘）

## 四、工作流（6 步，复用竞品监控模式）

1. **准备**：确认登录态（无效则弹二维码扫码）；确定关键词清单
2. **搜索**：Playwright 打开搜索页 → 设置「最多点赞」排序 + 「一周内」时间 → 滚动加载 N 条
3. **提取**：从 `window.__INITIAL_STATE__.search.feeds` 取结构化数据（标题 / 正文摘要 / 封面图 / 链接 / 点赞 / 作者 / 发布时间）
4. **图片处理**：封面图签名 URL 有效期短（约 30 秒），搜索完立即并发下载落盘；按笔记 id 去重
5. **汇总**：生成 `热门笔记-{日期}.csv`（标题 / 正文 / 封面图 / 链接 / 点赞 / 收藏 / 评论 / 作者 / 发布时间）
6. **看板**：生成瀑布流 HTML 看板（封面图卡片 + 点赞排序 + 关键词筛选 + 点击放大 + 下载 CSV）

## 五、数据字段（表格列设计）

| 列 | 字段 | 说明 |
|----|------|------|
| 排名 | rank | 按点赞降序 |
| 标题 | title | 笔记标题 |
| 正文 | desc | 正文（列表页摘要，完整正文见「七、难点」） |
| 封面图 | local_image | 本地封面图相对路径 |
| 链接 | url | 笔记详情页链接（含 xsec_token） |
| 点赞 | liked_count | 排序依据 |
| 收藏 | collected_count | 热度参考 |
| 评论 | comment_count | 热度参考 |
| 作者 | author | 笔记作者昵称 |
| 发布时间 | publish_time | 用于「近 7 天」校验 |

## 六、技术关键点

1. **数据来源**：小红书网页是 Vue SSR 渲染，搜索结果挂在 `window.__INITIAL_STATE__.search.feeds` 里，比爬 DOM 更稳、字段更全。
2. **筛选参数**：网页版原生支持「最多点赞」排序 + 「一周内」发布时间，无需自己二次过滤。
3. **登录态**：二维码扫码登录，Cookie（a1 / web_session / webId）持久化到本地复用，失效自动提示重扫。
4. **xsec_token**：详情页 token 与会话绑定，抓链接时必须带搜索结果里返回的 token。

## 七、难点与应对

| 难点 | 说明 | 应对 |
|------|------|------|
| 反爬 / 风控 | 频率敏感，过度抓取触发滑块验证码 | 频率控制（导航间隔 3–6 秒）、随机延迟、仿人滚动、UA 伪装；触发验证码则暂停冷却 |
| 封面图临时 URL | 图片 URL 带签名、约 30 秒失效 | 搜索完成后立即并发下载，不延迟 |
| 正文不完整 | 列表页只有标题 + 摘要，完整正文在详情页 | 两层策略：默认取列表摘要；需要完整正文时按需进详情页（`feed` 接口），控制在 Top N 内 |
| 登录失效 | Cookie 定期过期 | 运行前 `check-login`，失效自动弹码重扫 |

---

## 八、风险与合规

- **风控**：保持手动低频触发、串行抓取、随机延迟；不做高频自动定时抓取，避免账号受限。
- **合规**：仅用于个人学习研究，遵守小红书平台使用条款，不用于商业爬取或侵权用途。

## 十、待确认项（开工前需你拍板）
