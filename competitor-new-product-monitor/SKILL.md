# 竞品新品监控

把"盯竞品店铺新品"变成自动化流水线：每次运行产出 (1) 最新新品数据、(2) 与上一轮的变动对比、(3) 带真实图片的瀑布流看板。服务对象是经营珠宝/银饰/时尚饰品等类目的商家。

## 输入与目录约定

- 数据目录 `BASE`：默认当前工作目录下的 `jd-baseline/`；可用命令行参数覆盖（脚本均接受 BASE 作为第一参数）
- `BASE/stores.json`：店铺清单（序号、店名、平台、URL），首次需向用户收集，之后复用
- `BASE/jd_new_{序号}_{店名}.json`：本轮抓取数据（store/url/sort/fetched_at/count/items[]）
- `BASE/prev/`：上一轮抓取数据备份（对比用）
- `BASE/images/{序号}_{序号}.jpg`：下载的商品主图（n0 原图）
- `BASE/京东竞品新品瀑布流看板-{日期}.html`、`BASE/新品全量明细.csv`、`BASE/变动对比-{日期}.md`：交付物

## 工作流

### Step 1 准备
1. 检查 `BASE/` 是否存在。存在 `stores.json` 则读取店铺清单；否则向用户索要店铺链接（格式：平台 + 店铺名 + 链接），写入 `stores.json`
2. 若 `BASE/jd_new_*.json` 存在（上一轮数据）：先整体移动到 `BASE/prev/`（备份旧轮），再开始新抓取——这是对比的基础
3. 先问清/沿用用户确认的平台与店铺范围；不要默认扩大范围

### Step 2 抓取新品（关键：必须切「新品」排序）
**京东（mall.jd.com）**：页面是 JS 渲染，必须用浏览器子代理（`sessions_spawn` agent_id=browser），不能只靠 web_fetch。
- 打开店铺 view_search 列表页 → 点击排序栏的「新品」链接。点击后 URL 第 5 段 0→1（形如 `-0-1-0-0-`），即「新品」排序（按上架时间倒序，第一页就是最新款）。12/12 店铺实测有效
- 提取每个商品卡片：名称、价格（`.jdNum preprice`，滚动页面可触发渲染）、评价数、主图 URL（`li[data-src]`，完整 https）、商品链接
- 每店存一个 JSON（结构见下）；店铺序号与 stores.json 对应
- 价格接口（p.3.cn）与评价接口（club.jd.com）可能被网络限制导致部分价格缺失：先滚动触发补价，仍缺则保留为空并如实告知用户"价格待补"，**禁止编造价格**

**淘宝/天猫**：店铺分类页（`*.tmall.com/category.htm`）匿名访问会跳登录墙，web_fetch 拿不到商品 → **必须浏览器子代理**（用户 Chrome 需有淘宝/天猫登录态；若遇登录页，提示用户先登录/扫码后重试）。
- 新品排序：URL 带 `orderType=newOn_desc` 即按新品倒序（多数店铺链接已带）；没带的店铺（如秦福炫、宝恋）需点击页面「新品」排序按钮，或手动在 URL 加 `&orderType=newOn_desc`
- 提取：商品名、价格（注意活动价/划线价）、活动标签（如"新品""满减"）、主图 URL（img.alicdn.com，带尺寸后缀）、商品链接（detail.tmall.com/item.htm?id=...）
- 天猫图片尺寸后缀（`_60x60.jpg`、`_q50.jpg` 等）由 Step 3 的 fix_images.py 统一转原图
- 数据文件沿用 `jd_new_{序号}_{店名}.json` 命名（序号与 stores.json 对应，脚本可复用）；商品对象建议加 `activity` 字段记录活动标签

### Step 3 图片处理（含两层去重）
运行：`python {skill_dir}/scripts/fix_images.py {BASE}`
- **去重①（店内）**：每个店铺 JSON 先按商品链接去重——同一商品在列表页重复出现时只保留第一个（脚本自动处理并打印去重数量）
- 把全部 360buyimg 链接 `/n7/`（缩略图）替换为 `/n0/`（800x800 原图）
- 下载图片到 `{BASE}/images/{店序号}_{序号}.jpg`（并发 10 线程 + UA，失败自动重试 2 次，仍失败记录缺失清单并如实报告）
- 更新 JSON（n0 链接）与 `新品全量明细.csv`（含 image_n0、local_image 相对路径列）
- **去重②（CSV 全局）**：明细 CSV 按商品链接全局去重——同源店铺同一商品（如老凤祥自营与自营专区）只保留第一条，避免统计重复
- 注意：**不同店铺的同款商品不去重**（不同链接、不同价格，需分别观察），这是有意保留的

### Step 4 变动对比（有上一轮数据时）
运行：`python {skill_dir}/scripts/compare_new.py {BASE}`
- 按商品 URL 匹配新旧两轮：标记 **新增上架 / 下架 / 涨价(含幅度) / 降价(含幅度)**
- 输出 `{BASE}/变动对比-{日期}.md` 与终端摘要；无变化也要如实说"无变动"

### Step 5 瀑布流看板
运行：`python {skill_dir}/scripts/gen_dashboard.py {BASE}`
- 生成 `{BASE}/京东竞品新品瀑布流看板-{日期}.html`：全部新品瀑布流（图片固定卡片宽度、高度自适应、不压缩）、店铺筛选 chips、关键词搜索、价格排序、点击放大预览（lightbox）、统计条、下载 CSV
- 同源去重：老凤祥京东自营与自营专区为同一链接 → 按商品 URL 去重合并

### Step 6 交付
- `present_files`：看板 HTML（主交付）+ 变动对比 md + 明细 CSV
- 给用户讲清楚：新增/涨价/降价/下架数量、价格待补数量、下次如何触发（"跑一次竞品价格监控"）

## 关键经验（踩坑记录）

1. **京东新品排序**：view_search URL 第 5 段为 1（`-0-1-0-0-`）；点击页面「新品」按钮或直接改 URL 均可，实测 12 店全部有效
2. **图片 n7→n0**：360buyimg 规则，n7=缩略图、n0=原图；只替换 `360buyimg.com/n7/` → `/n0/`，不要全局替换 n7
3. **HTML 图片路径**：必须相对路径 `images/xx.jpg`（HTML 与 images 同在 BASE 下）；写 `jd-baseline/images/xx.jpg` 会路径重复 404
4. **序号解析**：`jd_new_01_xx.json` 用正则 `r'jd_new_(\d+)_'` 提取，不要 `split('_')[1]`（会取到 'new' 导致文件互相覆盖）
5. **宏乾专卖店**：URL 实际跳转到"豫铂专卖店"，以实际页面店名为准
6. **促销角标**：京东列表页不渲染促销角标，活动信息需进详情页；如用户要活动数据，对重点款抓详情页
7. **CSV 被占用**：Excel 打开 CSV 时写会失败 → 自动降级写 `_v2` 或提示用户关闭文件后重试
8. **看板/图片目录必须一起移动**：HTML 引用相对路径 images/，整个 BASE 文件夹一起拷贝

## 输出格式（固定模板）

- 看板 HTML：瀑布流卡片 = 主图(原图) + 店标签 + 商品名 + 价格 + 评价数 + 点击放大 + 京东链接
- CSV 列：store, title, price, comments, image_n0, local_image, url, id
- 变动对比 md：| 商品 | 店铺 | 变动类型 | 原价→现价 | 幅度 | 链接 |
